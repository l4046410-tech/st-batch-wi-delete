# 批量删除世界书条目

> v1.1.1 — 世界书多选、按书分组；修复手机上勾选的条目在删除时变成「没有勾选任何条目」。

SillyTavern 扩展。世界书条目多到要死的时候，能一次勾掉一堆删掉，而不是一条一条点。

## 安装

把整个文件夹放进：

```
SillyTavern/public/scripts/extensions/third-party/st-batch-wi-delete/
```

目录里应该是这三个文件：

```
manifest.json
index.js
style.css
```

然后刷新酒馆页面（Ctrl+F5）。扩展列表里会出现「批量删除世界书条目」，
展开后点它的设置面板就能用。

> 如果酒馆是 1.12 之前的版本，第三方扩展面板在 `#extensions_settings` 里也能正常显示，代码已兼容两种情况。

## 用法

1. 上面「选世界书」区域会列出全部世界书（**可多选**，带条目数徽标）
2. 勾一本或多本 → 下面按键自动加载，条目按书分组显示，每组头部有书名
3. 勾要删的条目（组头的复选框可以整本全选）
4. 点红色「删除选中条目」
5. 弹窗确认后，**每一本删除前都会各自下载一份备份 JSON**，然后才真正删除

### 快捷选择

| 按钮 | 作用 |
|---|---|
| 全不选 | 清空条目选择 |
| 反选 | 已选取消、未选选上（只作用于当前搜索结果） |
| 空条目 | 内容为空的条目——批量导入搞出来的垃圾（**跨书生效**） |
| 已禁用 | `disable: true` 的条目 |
| 重复内容 | 每本书内部内容相同的条目，**保留第一条**，其余选中 |

顶部还有「搜索世界书名称」和「全选 / 清空」，71 本书也能快速定位。

## 安全设计

- **删除前自动下载整本世界书的 JSON**，文件名带时间戳。删错了直接 World Info → Import 导回去
- 删除是二次确认，弹窗里会列出前 5 条的名称和总数
- 只调用世界书接口（`/api/worldinfo/get`、`/api/worldinfo/edit`），不直接碰文件系统
- 逐条 `delete data.entries[uid]` 后整体保存一次，不会出现删一半的中间状态

## 兼容性

依赖四个接口：`/api/worldinfo/list`、`/api/worldinfo/get`、`/api/worldinfo/edit`、`/api/worldinfo/delete`（本插件只用前三个）。

保存时优先调用 ST 自己导出的 `saveWorldInfo()`（会刷新缓存、发 `WORLDINFO_UPDATED` 事件）；
老版本没有导出就退回直接 POST `/api/worldinfo/edit`。

如果删完条目列表没刷新，切换一次世界书或者刷新页面即可——数据已经存盘了。

## 已验证

在 jsdom 里模拟了一套 ST 环境（面板容器 + 四个接口 + jQuery），跑了完整流程：

```
[1] 面板挂载 / 世界书列表 / 显示书名而非编号   4 ✔
[2] 多选：勾第一本 → 6 条渲染               2 ✔
[3] 多选：再勾第二本 → 两个分组 8 行          3 ✔
[4] 快捷选择「空条目」跨书生效               1 ✔
[5] 搜索 → 手工勾选 → 累计 3 条             2 ✔
[6] 跨书删除：两本各删各的、各自备份         8 ✔

结果：20 通过 / 0 失败
```

断言包括：接口返回数字 `file_id` 时界面仍显示真实书名、跨两本书分别删除各自的条目、两本各自触发备份、无关条目未被误删。

这是模拟环境，不是真酒馆；真机第一次用请拿一本**不重要的世界书**先试。

## 已知限制

- 不处理"删除整个世界书"（那是另一个功能，ST 自带）
- 备份文件是浏览器下载，走你的下载目录
- 一次删除大量条目（几百条）时保存会有一两秒延迟
