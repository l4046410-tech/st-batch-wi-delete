# 世界书批量删除（SillyTavern 扩展）

> v2.1 — 面板全部可折叠（总面板 + 两个功能区），折叠状态记在浏览器里，下次打开还是你上次的样子。
> 主功能：勾选一本或多本世界书，**一键删除整本**；删除前打包成一个备份 JSON。

## 安装

```
SillyTavern/public/scripts/extensions/third-party/st-batch-wi-delete/
```

目录里三个文件：`manifest.json`、`index.js`、`style.css`。放好后刷新页面（Ctrl+F5）。

## 折叠

面板分三层，点标题那一行就能折叠/展开：

```
▾ 世界书批量删除          ← 整体收起，只留一行标题
   ▾ ① 删除整本世界书      ← 默认展开
   ▸ ② 只删除书里的某些条目  ← 默认收起
```

折叠状态存在浏览器的 localStorage 里（`bwd_open_root` / `bwd_open_books` / `bwd_open_entries`），
刷新、下次打开都保持你上次的样子。

## 主功能：删整本世界书

1. 面板里列出全部世界书，每行带条目数徽标
2. 勾一本或多本（也可以「全选」）
3. 点 **「删除选中的 N 本世界书」**
4. 确认弹窗 → **先打包下载备份** → 再逐个删除服务端文件

想清空全部：点 **「删除全部 N 本」**，需要手动输入 `全部删除` 四个字才会执行。

### 备份长什么样

一次删除只下载**一个**文件，里面是 `{ "书名": {...完整世界书...}, ... }`。
一次下 N 个文件会被浏览器拦截，所以合成一个。

删错了怎么恢复：World Info → Import，选中那个 JSON 逐本导入；
或者直接解压出对应的书对象，改名存回 `data/<user>/worlds/<书名>.json`。

## 进阶：只删条目

面板下面折叠着「只删除书里的某些条目」。勾书目 → 条目按书分组列出 →
用快捷按钮（空条目 / 已禁用 / 重复内容）或手动勾选 → 删除。

删条目时**书本身保留**，走的是 `edit` 接口，删除前同样会下载备份。

## 接口与兼容

| 动作 | 首选 | 退回 |
|---|---|---|
| 列世界书 | `world-info.js` 的 `world_names` / `getWorldInfoList()` | `POST /api/worldinfo/list` → 读页面下拉框 |
| 读一本 | `loadWorldInfo()` / `loadWorldInfoData()` | `POST /api/worldinfo/get` |
| 删整本 | `deleteWorldInfo()` | `POST /api/worldinfo/delete` |
| 写回条目 | `saveWorldInfo()` | `POST /api/worldinfo/edit` |

请求头优先从 `script.js` 导入 `getRequestHeaders()`（带 CSRF token），
取不到再退回 `window.getRequestHeaders`，最后读页面的 csrf meta。
**没有 CSRF token 的 POST 会被服务端 403**——这是 v1.1 全部世界书「读取失败」的原因。

## 已验证

jsdom + jQuery 模拟酒馆环境（含「POST 无 CSRF token 就 403」的规则），跑真实点击流程：

```
[1] 列表：3 本、显示书名不显示编号              3 ✔
[2] 多选两本，按钮文案跟着变                    1 ✔
[3] 删除选中：两本文件真的没了、第三本没动、
    下载 1 次打包备份、列表只剩 1 本            6 ✔
[4] 删除全部：确认词不对不执行；输对后清空，
    两次批量删除各下载 1 次备份                 5 ✔
[5] 进阶：只删条目时书还在、走 edit 接口        3 ✔
[6] 没有任何 POST 被 403                       1 ✔

结果：28 通过 / 0 失败
```

这是模拟环境，不是真酒馆。第一次用请先删一本不重要的书确认行为。

## 已知限制

- 删除的世界书如果正被某个角色卡绑定，酒馆里那张卡会指向不存在的书（刷新后一般自动清空）
- 备份走浏览器下载，进你的下载目录
- 一次删除几百本会连续发几百个请求，慢但会一本本报告结果
